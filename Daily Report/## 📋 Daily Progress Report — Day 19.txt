## Story 19 — Dark Mode Toggle
**Epic:** epic-4 frontend | **Priority:** Medium | **Points:** 2 | **Estimate:** 0.5 day

---

### What I Did

Today I built a Dark Mode toggle system for the AI Code Mentor application. The goal was to allow users to switch between light and dark themes with their preference saved so it persists across browser sessions.

**ThemeContext** — I created `frontend/app/context/ThemeContext.tsx` which is a React Context that manages the theme state for the entire application. It uses `useState` to track the current theme as either light or dark. On first load it checks `localStorage` for a saved preference. If none is found it reads the system preference using `window.matchMedia('(prefers-color-scheme: dark)')` and defaults to whichever the user's OS is set to. When the theme changes it adds or removes the `dark` class from the root HTML element which triggers all the dark mode CSS styles. I also used a `mounted` state to prevent hydration errors that occur when the server renders a different theme than the client.

**ThemeProvider** — The `ThemeProvider` component wraps the entire application in `app/layout.tsx` so every page and component has access to the theme context. It exposes `resolvedTheme` which is either "light" or "dark" and a `toggleTheme` function that switches between the two and saves the choice to `localStorage`.

**Sidebar Toggle Button** — I updated `frontend/app/components/Sidebar.tsx` to import and use the `useTheme` hook. I added a toggle button at the bottom of the sidebar above the profile section. The button shows a 🌙 moon emoji and "Dark Mode" text when in light mode and a ☀️ sun emoji and "Light Mode" text when in dark mode. It also includes a visual toggle switch that slides right when dark mode is active using Tailwind's `translate-x` classes.

**Monaco Editor Theme** — I updated `frontend/app/components/CodeEditor.tsx` to use the `useTheme` hook. The Monaco editor `theme` prop now dynamically switches between `vs-dark` when dark mode is active and `light` when light mode is active. This ensures the code editor always matches the overall app theme.

**Dark Mode CSS** — I added dark mode CSS variables to `app/globals.css` using the `.dark` class selector. These override the default light theme colors for backgrounds, text, and borders across all pages and components.

**localStorage Persistence** — Every time the user toggles the theme the choice is saved to `localStorage` under the key `theme`. On the next visit the saved preference is loaded immediately so the user never has to set it again.
